# ADR-0135: Host allocation is attributed

- Status: Accepted
- Date: 2026-11-02
- Deciders: Optics Architecture Working Group
- Consulted: `flux` core, `prism` materials, `lens` core, `glyph` text stack
- Informed: Core Engineering
- Amends: [ADR-0129](0129-observation-plane-and-resource-ledger.md)
  (the host funnel gains ownership), [ADR-0134](0134-material-and-scene-attribution.md)
  (supersedes its "Recorded, not fixed" section)
- Does not amend: [ADR-0098](0098-developer-tooling-and-architecture-guardrails.md)
  (ABI gate is honoured by deleting the dead field, not suppressing it)

---

## Context and Problem Statement

`libs/flux/include/flux/core.h` has stated since the early API:

> Device-owned allocation passthroughs. Use these instead of libc malloc/free in
> peer code so the caller's allocator is honoured.

Measured compliance, after correcting an earlier miscount in this project's own
notes (the first figure recorded "glyph 32 sites"; the true count is 113, of
which 47 are platform-interop translation units):

| Library | libc sites | `flux_device_alloc` sites | Verdict |
|---|---|---|---|
| `prism` | 10 (5 alloc + 5 free) | 0 | violates |
| `lens` | 6 (incl. a legitimately device-less fallback) | 1 alloc + 1 free | partially violates |
| `glyph` (own TUs) | 66 | 0 | violates |
| `glyph` (CoreText/DirectWrite/fontconfig TUs) | 47 | 0 | **compliant** — see decision 4 |

Three deeper findings make this worse than a style inconsistency:

1. **The contract has never been tested.** `grep` for a test that installs a
   custom `flux_allocator` returns nothing. `test_alloc_fault.c` injects
   `vkAllocateMemory` (GPU-side), not the host allocator. A contract with zero
   verification is, by this repository's own standard (`invariants.md`), an
   aspiration.
2. **`flux_allocator.realloc` is dead.** No code path in any library calls it.
   It is a member of a public struct that has never been invoked, so its
   semantics are undefined by construction.
3. **The obvious fix breaks attribution.** `flux_device_alloc` funnels into
   `flux_internal_alloc`, which counts as `kind="host" owner="flux/core"`.
   Routing prism through it would have re-attributed every prism material to
   flux — re-introducing the exact misattribution ADR-0134 removed. The funnel
   must carry ownership *before* any library can adopt it.

## Decision Drivers

1. A contract that is violated by four libraries and verified by nothing must
   first become verifiable.
2. Attribution must survive adoption: routing a library through the funnel must
   not change who the leak is reported against.
3. The single-opts-descriptor convention applies to this entry point like any
   other; no `_ex` suffix, no extra positional parameters.
4. Dead public surface is deleted, not deprecated. A field nobody calls has no
   compatibility obligation.

## Architectural Decisions

### 1. `flux_device_alloc` takes a descriptor

The two positional-parameter entry points are replaced by one descriptor form:

```c
typedef struct flux_device_alloc_opts {
    flux_struct_type type; /* FLUX_TYPE_DEVICE_ALLOC_OPTS */
    size_t bytes;
    /* Who owns this memory, for the ledger row. Both must be literals. */
    const char *owner; /* "prism/material", "glyph/core", "lens/core" */
    const char *kind;  /* "filter_mica", "atlas", "store", … */
    flux_scope scope;  /* DEVICE for device-bound, CONTEXT for context-bound */
} flux_device_alloc_opts;

FLUX_NODISCARD FLUX_API flux_result
flux_device_alloc(flux_device *d, const flux_device_alloc_opts *opts, void **out);
```

`flux_device_free` likewise takes a descriptor:

```c
typedef struct flux_device_free_opts {
    flux_struct_type type; /* FLUX_TYPE_DEVICE_FREE_OPTS */
    void *ptr;
    const char *owner;
    const char *kind;
    flux_scope scope;
} flux_device_free_opts;

FLUX_API void flux_device_free(flux_device *d, const flux_device_free_opts *opts);
```

**Break clean.** The old signatures are deleted. This is a public ABI break,
which `ci-abi.yml` will flag; the abigail baseline is regenerated as part of
this change and no suppression is added. The two in-tree consumers (`lens`) are
migrated in the same commit; the Rust binding is regenerated by bindgen, and a
`#[deprecated]`-free break is the correct choice because the old form had no
way to express ownership.

Consequence worth stating plainly: **`free` takes the kind and owner again**,
because the ledger must release the row it acquired, and hosts may free through
a different call site than they allocated in. Requiring the caller to repeat the
pair is the price of not storing a side table, and it is checked: a release whose
(kind, owner) has no live acquisition is reported as an unmatched release by the
existing ledger mechanism.

### 2. The funnel is the only counted path, and it is scoped

`flux_internal_alloc` keeps counting for flux's own objects
(`owner="flux/core"`). `flux_device_alloc` now delegates with the caller's owner
and kind instead of discarding them, so:

- prism's filter memory reports as `owner=prism/material kind=filter_mica`;
- glyph's atlas reports as `owner=glyph/core kind=atlas`;
- flux's own objects are unchanged.

This is what makes adoption possible without regressing ADR-0134.

### 3. `realloc` is deleted from `flux_allocator`

The member has never been invoked. Deleting it:

- shrinks a public struct (ABI break, intentional, baseline regenerated);
- removes an undefined-semantics surface;
- forces any future growth path to state whether it is alloc+copy+free (which
  the ledger can observe) or something else.

`b_ndebug`-style compatibility shims are not offered.

### 4. Platform-interop TUs are exempt, by rule rather than by exception list

47 of glyph's 113 libc sites are in `txt_platform_font_coretext.c`,
`txt_platform_font_directwrite.c` and `txt_platform_font_fontconfig.c`. Those
allocate **foreign objects** (`CFStringRef` storage, `DWrite` buffers,
`FcPattern` nodes) that are handed to and freed by third-party APIs with their
own allocation domains. Routing them through the caller's allocator would be
incorrect: the foreign API's matching `free` runs inside the foreign API.

The exemption is expressed as a **path rule** in the guardrail, not as a list of
sites, and it is narrow: only the platform-interop TUs may call libc directly,
and only those three files are recognized.

### 5. The contract is verified by a hostile allocator

A new test installs a `flux_allocator` that:

- counts every allocation and free;
- poisons freed memory and asserts on use-after-free of the poison;
- fails the Nth allocation on demand, so every library's OOM path is driven;
- asserts at teardown that **every** allocation it handed out came back, per
  (owner, kind) — the same exact-delta discipline as the leak lanes.

The test then exercises prism, lens and glyph allocation paths and requires that
**the hostile allocator saw them**. A library that bypasses the funnel shows up
as "the hostile allocator received 0 bytes for owner=prism/material", which is a
direct, falsifiable assertion of the `core.h` contract — the thing that has never
existed.

### 6. The guardrail enforces the funnel

`tools/gate check leaks` gains a check: outside the exempt platform TUs and
outside `.c` files that own a device-less fallback (declared by an anchored
comment marker), a raw `malloc`/`calloc`/`free` in `libs/{prism,lens,glyph}` is
a failure. A new library cannot quietly join the non-compliant set.

## Alternatives Considered

### 1. Keep the positional signature and add `_ex`
- **Why considered**: no ABI break.
- **Rejected**: the repository forbids `_ex` tiers in `api-design.md`, and the
  3-parameter form cannot express ownership without a fourth and fifth
  positional argument. A descriptor is the house pattern and the ABI break is
  the honest cost.

### 2. Store (kind, owner) in a header before the pointer
- **Why considered**: `free` would not need to repeat the pair.
- **Rejected**: it changes the pointer the caller receives (breaking `realloc`,
  pointer arithmetic, and the poison test), and it puts a mutable header in
  front of memory the caller owns. Repeating the pair is checkable; a hidden
  header is not.

### 3. Deprecate `realloc` instead of deleting it
- **Why considered**: gentler for out-of-tree consumers.
- **Rejected**: "no backward compatibility, break clean" is the stated policy for
  this work, and a deprecated-but-present field still has undefined semantics.

### 4. Route prism through `flux_internal_alloc` unchanged
- **Why considered**: smallest diff.
- **Rejected on evidence**: it re-attributes prism leaks to `flux/core`,
  regressing ADR-0134. The funnel must carry ownership first.

## Consequences

### Positive
- The `core.h` contract becomes falsifiable for the first time.
- Attribution survives compliance: adopting the funnel does not blur ownership.
- The dead `realloc` field is gone rather than lingering as a trap.
- OOM behaviour of prism/lens/glyph host allocation becomes testable, which it
  never was.

### Negative & Trade-offs
- A public ABI break on `flux_device_alloc`, `flux_device_free`,
  `flux_allocator`, `flux_arena`, and the regenerated `symbols.md`. The abigail
  baseline must be regenerated; no suppression is added.
- `free` requires the caller to repeat (kind, owner). That is a real ergonomic
  cost and is mitigated only by the unmatched-release report, not eliminated.
- Migration touches 66 glyph sites and their call chains, several of which need
  a `glyph_ctx *` threaded to the allocation point (`glyph_cache` currently has
  none and must gain one).
- The guardrail's raw-libc check will be noisy while migration is in progress;
  it is introduced with the exemption marker so the tree stays green at each
  step rather than at the end.

## Acceptance Criteria

1. `flux_device_alloc` / `flux_device_free` take descriptors carrying
   `owner`/`kind`/`scope`; the positional forms no longer exist.
2. `flux_allocator.realloc` is deleted and `flux_arena` no longer carries it.
3. A hostile-allocator test proves prism, lens and glyph each route their
   allocations through the caller's allocator, and that every byte returned came
   back, per (owner, kind).
4. `tools/gate check leaks` fails on a raw libc allocation in a non-exempt
   `libs/{prism,lens,glyph}` TU.
5. `./tools/gate check` is green; the ABI baseline is regenerated with no new
   suppression; `docs/reference/symbols.md` is regenerated.
