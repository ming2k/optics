# ADR-0160: Unified Optics C Facade and Umbrella Distribution

- Status: Accepted
- Date: 2026-11-12
- Scope: `include/optics/optics.h`, `meson.build`, `tests/optics/`
- Amends: [ADR-0023](0023-unified-monorepo-build.md), [ADR-0106](0106-monorepo-identity-unification-glyph-vista-transit.md)

## Context

Optics enforces strict architectural boundaries across seven micro-libraries under `libs/`:
- **Layer 0 (`flux`)**: Vulkan 1.3 RHI, 2D vector canvas (GPU & CPU fallback), analytic curve kernel;
- **Layer 1 (`glyph`)**: HarfBuzz-backed text shaping and dynamic atlas cache;
- **Layer 2 (`prism`, `vista`, `transit`)**: Dielectric glass shaders, 3D glTF scene hierarchy, and header-only motion math;
- **Document (`svg`)**: Static vector art document compiler;
- **Layer 3 (`lens`, `iris`)**: Retained/immediate UI engine and native OS windowing shell.

While internal link-time isolation and strict decoupling prevent dependency cycles and architectural spaghetti, external C/C++ consumers previously faced significant integration friction:

1. **Header Proliferation**:
   An application developer building a complete GUI program was required to remember and maintain an escalating list of disparate subsystem headers (`<flux/flux.h>`, `<lens/lens.h>`, `<iris/iris.h>`, `<transit/transit.h>`, `<glyph/glyph.h>`, etc.).
2. **Build Configuration Complexity**:
   Downstream build scripts had to discover and link 6 to 8 separate `pkg-config` packages (`flux.pc`, `lens.pc`, `iris.pc`, `glyph.pc`, `transit.pc`, etc.) rather than linking against a singular engine identity.
3. **Absence of Top-Level Engine Versioning**:
   While individual subsystems provided `FLUX_VERSION_NUMBER`, `LENS_VERSION_NUMBER`, etc., there was no single authoritative `OPTICS_VERSION_NUMBER` macro representing the consolidated stack release.

## Decision

Introduce a canonical, first-class **Optics C Facade and Umbrella Distribution** model without violating the internal architectural boundaries of the underlying sub-libraries:

1. **Single Canonical Header (`<optics/optics.h>`)**:
   - Placed at `include/optics/optics.h` and installed into `${prefix}/include/optics/`.
   - Defines authoritative stack version constants: `OPTICS_VERSION_MAJOR`, `OPTICS_VERSION_MINOR`, `OPTICS_VERSION_PATCH`, and packed `OPTICS_VERSION_NUMBER`.
   - Leverages standard C23 `__has_include` directives to cleanly expose all enabled subsystems (`flux`, `glyph`, `prism`, `vista`, `transit`, `svg`, `lens`, `iris`) in proper layer-order without requiring consumer preprocessor flags.
2. **Unified Meson Dependency (`optics_dep`)**:
   - Declared in the root `meson.build`.
   - Bundles the top-level include path (`include/`) with the sub-library dependencies of all enabled modules.
   - Internal test suites, benchmarks, and examples can bind to `optics_dep` directly.
3. **Canonical Pkg-Config Package (`optics.pc`)**:
   - Generated by Meson in the root project.
   - Declares `Requires:` for all enabled component packages (`flux`, `lens`, `iris`, `transit`, etc.) and specifies `Cflags: -I${includedir}`.
   - Downstream projects integrate the entire Optics engine with one declaration:
     ```sh
     pkg-config --cflags --libs optics
     ```
4. **Automated Facade Regression Suite**:
   - A dedicated C23 integration test (`tests/optics/test_optics_facade.c`) links against `optics_dep` and exercises cross-layer functionality (version invariants, Flux vectors/rectangles, Transit spring dynamics, Lens/Iris structures) to ensure the umbrella facade remains compile-clean and complete.

## Dual-Track Distribution & Granular Linking Guarantees

The introduction of the umbrella facade explicitly does **not** create a monolithic `liboptics.so`. Optics retains dual-track distribution:

1. **Granular Component Distribution (First-Class Citizen)**:
   - Every subsystem continues to produce its own dedicated shared object (`libflux.so`, `liblens.so`, `libiris.so`, etc.) or header-only contract (`transit`).
   - Every subsystem continues to install its own granular package config (`flux.pc`, `lens.pc`, `transit.pc`, etc.).
   - Headless backends, offline renderers, and CLI tools that only require Layer 0 graphics must continue to link against `flux.pc` (`#include <flux/flux.h>`). This guarantees zero linkage against `libiris.so`, zero Wayland/Win32/Cocoa dependencies, and zero typography runtime overhead.

2. **Umbrella Application Distribution (Convenience Meta-Package)**:
   - `optics.pc` acts strictly as a meta-package specifying `Requires:` on enabled components.
   - Including `<optics/optics.h>` provides declarations across all enabled layers, but only functions actually invoked by the consumer will produce undefined references if a consumer links against a granular library.
   - Standard modern toolchains employing `-Wl,--as-needed` naturally strip unreferenced shared library entries from the final ELF `DT_NEEDED` list.

## Anti-Patterns & Negative Knowledge

- **Monolithic `.so` Anti-Pattern**: Optics rejects creating a single `liboptics.so` containing all layers. A monolithic shared library would permanently bind Layer 0 rasterization to Layer 3 desktop windowing, destroying headless and embedded deployment targets.
- **Indiscriminate Umbrella Linking in Headless Targets**: A headless worker or server daemon must not link against `optics.pc` if it only requires `flux`. Doing so introduces unneeded system dependencies (`wayland-client`, `xkbcommon`, `harfbuzz`) into container deployment images.

## Consequences

Positive:
- **Streamlined Consumer Ergonomics**: Downstream C23 applications include `<optics/optics.h>` and link `optics.pc`, mirroring the ergonomics of unified modern stacks like Skia or SDL3.
- **Preserved Architectural Purity**: The umbrella facade is purely distributive. Internal layer constraints (e.g. ADR-0063 Layer 0 isolation, zero libc allocs in frame walks) remain strictly enforced at the build and linker levels.
- **Unified Engine Identity**: Synchronized C-side umbrella distribution mirrors the unified Rust `optics` facade crate (ADR-0159).
- **Zero Unwanted `.so` Bloat**: Dedicated and specialized consumers retain full granular independence through per-subsystem `.pc` and header entry points.

Negative / Neutral:
- Builds installing Optics now generate and install `optics.pc` and `include/optics/optics.h` alongside the per-library files.
