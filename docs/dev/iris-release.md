# Release

How to cut a iris release. There is no release automation today; this is
the manual, repeatable procedure a maintainer follows.

## Preconditions

- On `main`, clean working tree, all intended changes merged.
- flux and lens at the versions iris targets are released (iris
  discovers them via `pkg-config`; `Requires: lens >= 0.1.0` in
  `iris.pc`).
- Local build of the full stack passes both the `test` and `stubs`
  configurations (see [Build and test gates](#build-and-test-gates)).

## Versioning and changelog steps

iris uses semantic versioning. The version lives in two places that
must stay in sync:

| Location | Field |
|----------|-------|
| `meson.build` | `version : '0.1.0'` |
| `libs/iris/include/iris/app.h` | `IRIS_VERSION_MAJOR / _MINOR / _PATCH` macros |

Steps:

1. Bump the version in both places.
2. Move the `## Unreleased` section of [CHANGELOG.md](../../CHANGELOG.md)
   under a new `## <VERSION> — <YYYY-MM-DD>` heading.
3. Add a fresh `## Unreleased` section above it for the next cycle.

The library soname and `iris.pc` version derive from `meson.build`, so
no separate soname bump is needed. (Rust crate versions live with the
bindings in the separate iris-rs repository.)

## Build and test gates

Run the same gates CI runs (see the
[CI workflow](../../.github/workflows/ci.yml)):

```sh
# full stack: flux -> lens -> iris, installed into $PREFIX
meson setup --prefix=$PREFIX build -Dexamples=true -Dtests=true
meson compile -C build && meson install -C build
meson test -C build
```

Also build the stub configuration (libsystemd absent) to confirm the
fallback translation units compile and pass:

```sh
meson setup --wipe build-stubs -Dtests=true   # on a host without libsystemd,
meson compile -C build-stubs                  # or after uninstalling it
meson test -C build-stubs
```

Confirm `iris_version_string()` reports the new version:

```sh
./build/libs/iris/tests/test_version
```

## Artifact creation and publication

1. Commit the version bumps and the changelog entry.
2. Tag the release:

   ```sh
   git tag -a v<VERSION> -m "iris <VERSION>"
   git push origin main --tags
   ```

3. Let CI run on the tag. Both the `test` and `stubs` jobs must pass.
4. Publish a GitHub release from the tag, pasting the changelog section
   as the release notes. Source tarball + checksum are generated by
   GitHub from the tag.

## Post-release checks

- The new `## Unreleased` section exists in
  [CHANGELOG.md](../../CHANGELOG.md).
- The two version fields still match (`meson.build`, `app.h` macros).
- `iris_version_string()` returns the released version.
- The GitHub release is marked as the latest.
